## Proposal 1: transcript hook's unique-anchor rule can be unsatisfiable by the Edit tool

**Type:** Backlog Proposal (tooling defect)
**Priority:** Medium

**Problem statement.** `.claude/hooks/validate-transcript-edit.sh` check 1/3 requires
`old_string` to be anchored to the **last non-empty line** of the transcript. The Edit
tool separately requires `old_string` to be **unique** in the file. When the last
non-empty line is a short string that occurs earlier in the file, these two constraints
are mutually unsatisfiable: the anchor the hook demands is the anchor Edit rejects.

**Observed S57.** The transcript's last non-empty line was `Accepted.`, which occurred
twice. Edit failed with "Found 2 matches"; supplying more context to disambiguate then
failed the hook with "old_string is not anchored to the last non-empty line". The append
was only possible via the Bash-heredoc fallback documented in the project CLAUDE.md.

**Why it matters.** The heredoc fallback exists and works, but it is documented as an
*anti-pattern guard* (do not use quoted heredocs with shell expansions) rather than as
the designated escape hatch for this failure mode. An agent that has not internalised
both rules may retry the Edit, widen the anchor, or, worst case, reach for
`replace_all`, which is the exact operation the hook's check 0/3 exists to prevent and
which produced a 95 MB transcript in IronCalc S17.

**Proposed resolution (one of):**
1. Have check 1/3 accept an `old_string` that *ends with* the last non-empty line, so a
   multi-line anchor spanning the final two lines satisfies both constraints. Cheapest
   fix, no agent-side behaviour change.
2. Document the heredoc fallback explicitly in the hook's failure message, so the
   remediation path is in the error rather than only in CLAUDE.md.

Option 1 is preferred: it removes the conflict rather than teaching around it.

## Proposal 2: `/dsm-align` describes `last-align.txt` and `last-align-report.md` as gitignored; in this repo they are tracked

**Type:** Backlog Proposal (spec/reality mismatch)
**Priority:** Low

**Problem statement.** `/dsm-align` Step 12a states the persistent report "is gitignored
via the existing `.claude/` rule; no `.gitignore` change required", and Step 13 calls
`last-align.txt` "gitignored, local state". In this project `git check-ignore` reports
neither file as ignored, and both are tracked in git.

**Cause.** The claim assumes Claude Code's `.git/info/exclude` blanket `.claude/` rule.
That rule is per-clone infrastructure, not a repository guarantee, and this repo tracks
`.claude/` deliberately (CLAUDE.md, hooks, settings, reasoning lessons and transcripts
are all versioned).

**Why it matters.** An agent following the spec would not stage these files, so a
post-change alignment would silently fail to commit its own markers, and the next
session's version check would read a stale `last-align.txt`. S57 caught this only by
running `git check-ignore` instead of trusting the spec.

**Proposed resolution.** Reword both steps to "gitignored in projects that exclude
`.claude/`; otherwise tracked, stage with the session commit", and have the step verify
rather than assert.

## Proposal 3: Template 8's Sprint Boundary Checklist and the §17.1 spoke reinforcement can diverge without either being wrong

**Type:** Backlog Proposal (protocol gap)
**Priority:** Medium

**Problem statement.** DSM_2.0.C §1 Template 8 defines a 9-item Sprint Boundary
Checklist that lands in sprint plan files. Projects also reinforce a sprint-boundary
checklist in `.claude/CLAUDE.md` project-specific content. Nothing reconciles the two,
and nothing declares which is authoritative.

**Observed.** This project carried a 7-item list in CLAUDE.md and the canonical 9 in its
sprint plans. Flagged in S55, unresolved until S57. The framing "7 vs 9" was itself
misleading: on an item-level diff, **neither list was a subset of the other**. CLAUDE.md
omitted 4 canonical items (tests passing, smoke-tests currency, blog publication tracker,
next-steps summary) and carried 2 items the template does not have (epoch plan updated,
hub/portfolio notified). A naive "adopt the canonical 9" reconciliation would have
silently deleted two legitimate local practices.

**Why it matters.** `/dsm-go` Step 3.6 hard-gates sprint closure on the presence of the
`## Sprint Boundary Checklist` section, but compares against an ambiguous standard when
two divergent lists exist. The gate can pass while the project runs the wrong checklist.

**Proposed resolution.** State an authority rule in §17.1: the sprint plan's checklist is
Template 8 verbatim, and project-specific additions are permitted but MUST be marked
(e.g. a `**Local:**` prefix) and MUST appear in both places. Optionally add a `/dsm-align`
detective check that diffs the two lists item-wise and warns on divergence, since a count
comparison would have missed this case entirely.

## Proposal 4: `/dsm-align` Step 12a claims `last-align-report.md` content is identical between runs; the timestamp line is not the only difference

**Type:** Observation (minor)
**Priority:** Low

Step 12a asserts idempotence "excluding the timestamp line". In practice the DSM version
line, warning counts and the "already correct" tally also change between runs whenever
Central has moved. Not a defect, but the stated invariant is narrower than written and
could mislead a diff-based check. Suggest rewording to "excluding the header block".
